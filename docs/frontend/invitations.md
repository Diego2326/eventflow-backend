# INV / GST: invitaciones, RSVP y acceso

El organizador crea invitaciones en `POST /api/events/{eventId}/invitations` con `{ "guestName": "Ana", "guestEmail": "ana@example.com", "allowedCapacity": 2, "table": "Mesa 1", "seat": "A1", "sector": "Norte" }`. La respuesta devuelve `token` y `qrPayload` **solo al crear o regenerar**; conserva el token para compartirlo. `GET` en la misma ruta lista invitados. Usa `POST .../{id}/revoke` o `/regenerate` para invalidar el acceso anterior. `PATCH .../{id}/seat` reasigna mesa/asiento/sector con control de cupo y duplicados.

Con el token sin cuenta: `GET /api/invitations/access/{token}` y `/experience`, `POST /api/invitations/access/{token}/rsvp` con `{ "accepted": true, "companions": ["Luis"] }`. La experiencia incluye evento, módulos, agenda, avisos y mapa permitidos para esa invitación. El token se puede vincular a una cuenta mediante `POST /api/invitations/access/{token}/link`; también existe `POST /api/invitations/link` con `{ "tokens": ["..."] }`. Con cuenta vinculada usa `GET /api/invitations/mine`, `GET /api/invitations/{id}/experience` y `POST /api/invitations/{id}/rsvp`.

El personal con permiso `CHECK_IN` registra ingreso/salida con `POST /api/events/{eventId}/invitations/{id}/check-in` o `/check-out` y `{ "quantity": 1 }`. Para escanear, usa `POST /api/events/{eventId}/check-in` o `/check-out` con `{ "qrPayload": "eventflow:invite:...", "quantity": 1 }`. Envía el `qrPayload` exacto recibido, no construyas uno con el UUID. El backend comprueba RSVP aceptado, vigencia, cupo y reingreso. `GST:SEATING_AREA` configura mesas desde el motor de datos modulares.

Para un grupo confirmado, `memberIndex=0` representa al titular y los índices 1..N siguen el orden de `companions` del RSVP. Envía `{ "quantity": 1, "memberIndex": 1 }` al registrar un integrante, también en el check-in por QR. `InvitationResponse.members` muestra `index`, `name` e `inside` para cada integrante; `inside=null` significa que la invitación se registró con conteos agregados y no se conoce el estado individual. No mezcles check-in agregado con individual para la misma invitación: el backend responde 409.
